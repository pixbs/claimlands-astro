# Architecture

Claim Lands shares Rust game code between iOS, Android and browser WebAssembly. There is no Windows game target; host-native tests exercise portable libraries. The product is a procedural, turn-based strategy game. Multiplayer is outside the MVP.

## Boundaries

```text
game application ──► world ──► versioned RON contracts
       │               ▲
       ├──────────► visuals
       │               ▲
       └──────────► renderer
```

Arrows mean code dependencies. The application resolves a `World`, generates `PlanetAssets`, and supplies those buffers to the renderer.

| Component | Owns | Must not own |
| --- | --- | --- |
| `crates/world` | Stable tile graph, terrain generation, RON validation, immutable initial board | Graphics, input, storage, networking, wall-clock time |
| `crates/visuals` | Procedural CPU mesh and RGBA texture buffers | GPU handles, authoritative game mutations |
| `crates/renderer` | GPU surfaces/resources, WGSL, presentation | Economy, occupation or turn rules |
| `apps/game` | Entrypoints, lifecycle, input, camera, development interface | Duplicated rules for each platform |
| `tools/xtask` | Reproducible developer/CI commands and task preparation | Runtime game behavior |

`cargo xtask boundaries` checks allowed production dependencies through Cargo metadata. Workspace lints reject unsafe Rust by default; platform ABI exports carry local, documented exceptions. Prefer private state, typed identifiers and explicit errors. Add abstractions for concrete variation, not hypothetical future features.

## Current scaffold

- `Topology::generate` builds the dual of a subdivided icosahedron: `10n² + 2` tiles, including 12 pentagons, for frequencies 2–12. Tile identity comes from integer topology construction; geometric coordinates do not determine identity.
- `LevelDefinition::from_ron` parses bounded data and validates it before `World::generate` resolves terrain and sparse overrides. Seed zero produces a water base; explicit editor overrides apply afterward.
- `World` exposes immutable tiles. Its fingerprint hashes discrete tile state and adjacency in stable order; it is not yet a save/replay format.
- `PlanetAssets::generate` creates terrain triangles and a procedural texture atlas. The renderer presents a low-resolution scene with nearest sampling. The application provides rotation, zoom, tile selection and regeneration controls.
- Android/iOS entrypoints and browser startup share application code. Compilation and runtime validation are separate acceptance requirements; entrypoints alone do not prove mobile packaging or lifecycle correctness.

The scaffold does not implement economy, units, territory resolution, AI or victory. Tile content and faction settings are initial-state data. Current terrain is an initial rendering slice, not an approved match to the reference prototype.

## Simulation contract for the next milestone

Add a `gameplay` crate when the first rule is implemented. It depends on `world`, with focused modules for territory, economy, units and turns. Human input, AI and future multiplayer submit the same validated commands. Rendering consumes a read-only view; events describe accepted transitions and never become a second rules engine.

Each command either fails without changing state or applies one atomic transition. A capture resolves combat, occupation, connected components, capitals and treasury allocation together. Integer resources, stable ordering and explicit seeded randomness keep results reproducible. Cosmetic randomness must never advance the simulation stream.

Undo initially restores full snapshots, including random state and statistics. Committing the faction turn closes that undo boundary. Future saves/replays retain a resolved initial board, rules/generator versions and committed commands; generator changes must not rewrite old sessions. Hash the authoritative state independently of rendering and RON whitespace.

AI and the internal editor become separate components when they have working behavior. Networking belongs in an adapter around the command interface. No network behavior belongs inside the rules engine. Resolve the mechanics listed in [decisions.md](decisions.md) before implementing their dependent rules.

## Visual contract

The external HTML prototype is visual reference material, not a dependency or source to copy into the game. All product models and textures are generated by original Rust/WGSL code. Minimal browser HTML and generated WebAssembly loading glue are infrastructure.

The fidelity milestone must match grass/water palettes and patterns, coastal slopes and foam, connected field parcels, trees and understory, house geometry, pixel sampling, lighting, atmosphere, background stars, and cloud shape/dithering/zoom transparency. New pawn, capital and action-star models need their own approved designs where the reference provides none.

Use fixed seeds, camera poses, viewport sizes and animation time to compare reference images. Preserve approved baselines independently of proposed changes. CPU geometry checks and image comparisons answer different questions; both are needed. See [testing.md](testing.md).
